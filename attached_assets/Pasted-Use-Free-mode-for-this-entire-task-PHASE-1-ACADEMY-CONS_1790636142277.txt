── 1. TENANCY: academy_members ──
New table academy_members, modeled exactly on the field_owners precedent:
user_id, academy_id, role ('owner' | 'coach'), unique on (user_id, academy_id,
role). A user can be a member of multiple academies and can hold both roles.
Server-side helper that resolves the current user's academy memberships;
EVERY console endpoint must enforce membership (and role where relevant)
server-side, per-route, following the owner.ts pattern. Never UI-only gating.

── 2. FULL v1 SCHEMA NOW (one DB push for all phases) ──
Design and create ALL v1 tables in this task, even though most features come
later, so we do exactly one schema push:
- academy_members (above)
- academy_squads (academy_id, name, optional description/age-group)
- academy_players (academy-owned roster record: academy_id, squad_id nullable,
  name, optional jersey number, optional position, optional date of birth,
  optional guardian phone, optional linked user_id nullable, active flag)
- academy_sessions (academy_id, squad_id, type training|match, starts_at UTC,
  optional ends_at, location text, optional opponent name, optional our/their
  score for manual match results, optional notes)
- academy_attendance (session_id, player_id, status present|absent|late|excused,
  unique on session_id+player_id)
- academy_fees (academy_id, player_id, label, amount_fils integer, due_date,
  status due|paid|waived, optional paid_at, optional note) — JOD via the
  existing amount_fils integer precedent
- academy_announcements (academy_id, optional squad_id, title, body, created_by,
  created_at)
All timestamps stored UTC; display in Amman time using the same approach as
owner.tsx. Spec-first: add the new endpoints to openapi.yaml (NO query
parameters — path/body only, per our Orval constraint), run codegen, and keep
the schema additive so `pnpm --filter db run push` shows only green additions.
